Architectural Philosophy: The Agentic REPLTo recreate Claude Code, one must first understand that it is not merely a chatbot; it is an intelligent, recursive Read-Eval-Print Loop. Traditional CLIs are imperative and linear: the user inputs a command, the system executes it, prints the output, and returns to a prompt. An agentic CLI, however, introduces a dynamic "evaluation" phase where the system may execute multiple internal cycles of reasoning and tool use before returning control to the user.2.1 The "nO" Master Loop DesignThe core architecture of Claude Code relies on a concept internally codenamed "nO".9 This is a single-threaded master loop that prioritizes simplicity and auditability over the complexity of multi-agent systems. For our local implementation, this design is superior to "agent swarms" because local models (often 7B to 32B parameters) struggle with the context switching overhead required by multi-agent orchestration.The loop follows a strict sequence:Input Acquisition: The system captures user input or the output from a previously executed tool.Context Augmentation: The logic engine retrieves relevant context (file contents, CLAUDE.md rules, git status) and constructs a prompt.Inference (Thinking): The prompt is streamed to Ollama. The UI displays a "Thinking" spinner.Action Determination: The model outputs either a natural language response (terminating the loop) or a structured "Tool Call" (continuing the loop).Execution & Observation: The system executes the requested tool (e.g., reading a file) and captures the output.Recursion: The tool output is appended to the message history, and the loop restarts from Step 2, allowing the model to analyze the new data.9This "flat message history" approach ensures that the agent retains a coherent narrative of its actions, which is critical for debugging and for the user to understand why the agent made a specific change.2.2 The React-in-Terminal ParadigmStandard CLI libraries (like readline or inquirer) operate by printing text strings to stdout. This approach is insufficient for an agentic workflow where the UI must simultaneously display:Streaming responses from the LLM.Spinners indicating background processing.Collapsible logs of tool outputs (to prevent terminal pollution).Interactive permission prompts (Allow/Deny tool use).To achieve the "Claude Code" UX, the architecture must utilize React Ink.3 Ink serves as a React renderer for the terminal, using the Yoga layout engine (based on Flexbox) to calculate text positioning. This allows the CLI to be built as a tree of React components. Crucially, Ink implements a "reconciliation" process similar to the browser DOM: when the agent's state changes (e.g., a tool finishes executing), React calculates the minimal set of changes required and updates the terminal display efficiently.8 This eliminates the "flickering" associated with clearing and redrawing the screen and allows for rich, interactive elements like scrollable lists and toggleable visibility states.123.
